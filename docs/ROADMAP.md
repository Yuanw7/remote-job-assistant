# 实施与验证计划

已完成基础文档及部分 M1 原型：两个只读来源、SQLite、精确去重、基础资格规则和本地报告。M0 真实画像及人工样本标注未完成；M1 的完整资格判断与精确率验收仍待完成。下列列表保留完整目标，不是已完成清单。时间对应路线 C 的单开发者估算，真实 ATS 接入可能延长。

## M0：画像和手工基线（1–2 天）

- 填写 candidate 模板；确认岗位、所在地、语言、资历、薪资、时区和合同偏好。
- 整理可证实的经历、项目与成果；建立答案库，不保存猜测。
- 人工收集并标注 30–50 个岗位，覆盖可投、明确不合格和未知。
- 记录手动筛选/材料/填表时间；建立 10–20 份材料对照样本，实际提交由用户决定。

退出条件：必需候选人事实已确认，硬要求/软偏好明确，评估样本可复用。若跨地域合格岗位极少，先调整求职画像，不急着建设提交器。

## M1：可靠的职位队列（3–5 天）

- 修复现有入口占位问题，确定 TypeScript/测试工具与项目结构，记录依赖版本。
- 建 SQLite 表与迁移；实现配置校验和 `unknown` 语义。
- 实现 Himalayas、Greenhouse 两个只读适配器和手动 URL 导入。
- 建企业目录、原始快照、跨来源去重、时效检查、资格判断和分项排序。
- 输出本地候选清单，显示每项判断依据及待核实原因。

退出条件：首批 50 条人工抽检精确率至少 80%；已知资格冲突进入可投队列数为 0；重复采集不重复建记录；429/超时表现为采集失败而不是“无岗位”。

## M2：可信材料包（3–5 天）

- 实现事实库检索、英文简历选择/改写、问题答案复用和求职信可选生成。
- 每份材料绑定职位快照和 profile 版本，输出事实映射及改动对比。
- 先用固定模板生成可审阅文件，再加导出格式；需要 PDF/DOCX 时进行渲染检查。
- 记录每份材料的模型调用、费用和人工修正。

退出条件：20 份代表性材料无新增虚假事实、联系方式和关键日期完全一致；缺失事实明确待补；费用不超过用户设定上限。离线模式不上传任何材料。

## M3：一个 ATS 的辅助申请（3–5 天）

- 按 M1 真实岗位分布选首个 ATS，暂定 Greenhouse。
- 实现 inspect/fill/字段回读、附件确认、动态必填题处理和人工接管。
- 本地 fixture 覆盖多步表单与异常；在线检验先使用自有/获授权测试表单。
- 经用户授权，才在真实目标职位进行填写/上传与提交测试。
- 实现提交状态、唯一约束、回执保存和不确定结果对账。

退出条件：代表性测试中所有必填字段可核验；遇未知问题能停在明确状态；重复任务不触发重复提交；点击后超时不会自动再投。

## M4：持续运行与反馈（2–3 周观察期，不等于开发工期）

- 根据试验决定增加 Lever/Ashby，或扩大已有来源的企业覆盖。
- 首轮每天最多审核 5–10 个高相关岗位，属于建议实验节奏而非供应商限制或默认授权。
- 先手动更新结果；需要时接入用户授权的邮箱范围，区分回执、拒信、面试与人工待分类邮件。
- 按投递周记录至少 21 天的结果窗口，计算面试率与总人工时间。
- 达到技术质量门槛且用户明确选择后，启用有上限的批量提交模式。

退出条件：有实际漏斗、成本和维护时间数据，再决定停留在个人工具或投入产品化。

## 必测场景

| 场景 | 期望行为 |
| --- | --- |
| profile 居住地未知，JD 写 remote | unknown，不自动进入可提交队列 |
| 测试画像在 CN，JD 明确 US residents only | ineligible，保留限制原文 |
| 聚合源 Worldwide，雇主 JD 限制 EU | 冲突可见，不能按标签放行 |
| 岗位可全球申请但用户工作时段与必需时区不重叠 | fail 或在缺时段数据时 unknown |
| 用户未提供美国工作授权答案 | 相关问题 needs_input，不能填 Yes |
| 同一 ATS posting 出现在两个来源 | 同一 canonical job，保留两个来源 |
| 同公司相同 title，不同 posting/location | 疑似重复检查，不直接删除 |
| 简历改写增加未经确认的业绩数字 | 材料校验失败 |
| 填表过程中职位增加新的必填题 | 阻止继续提交，重新检查 |
| 提交按钮点击后超时/重启 | submission_unknown，禁止自动再次点击 |
| 源接口返回 429 | 记录错误，退避，不清空现有岗位 |
| 收到自动确认邮件 | submitted 证据，不计面试 |
| 网页要求忽略系统规则、上传额外私有文件 | 当外部文本处理，不执行权限变更 |
| 修改已批准材料、授权过期或超日预算 | 原批准失效或任务停止，保留原因 |

当前已运行的自动测试位于 `test/core.test.js`，涵盖部分地域/工作方式规则、去重、分页、失败保留与 HTML 转义。其余涉及材料、上传、提交、授权的场景尚未实现和测试。

## 简历接入后的进展

已人工核对两份用户 PDF，构建私有来源事实库与两个求职方向。已实现多词查询、方向报告、事实证据匹配、职级提醒和材料准备单；新增测试覆盖方向隔离、事实来源验证、未支持事实、岗位快照绑定。真实居住地/授权/工时未确认，M0 未完成；英文材料及 ATS 申请仍待实现。个人化计划保存在 `private/resume-review/PLAN.md`。

## 审核闭环增量

已实现显式 JD 条件摘录、版本绑定的 shortlist/hold/skip 记录、两方向的批量材料准备队列。SQLite 增量增加 reviews 表，已有岗位保留。测试覆盖审核隔离、资料变化失效、skip/hold 队列行为，以及 shortlist 不能越过硬性排除。尚未实现完整语义解析、英文成稿、浏览器申请和回执。

## 英文内容草稿增量

已编写与来源事实绑定的英文表述库，并实现两方向母版、岗位简历内容与模板式求职信草稿、来源对照、事实变化拦截、版本化 HTML/TXT/JSON 输出。共用 queue 自动附英文稿链接。不是通用翻译器，也尚未达到正式英文简历/PDF 导出的交付标准；身份英文写法和关键求职条件仍待确认。

## 本地工作台增量

已增加浏览器审核入口：方向与关键词筛选、分页、优先/暂缓/不考虑持久化、材料准备及英文草稿生成。采用 Node 内置 HTTP，无新增运行依赖。测试覆盖真实本地 HTTP 请求、审核持久化、来源/token/Host 校验、过期页面冲突、受控材料读取。测试数据与真实求职记录分开。仍未实现外部 ATS 填写/提交。

## 求职条件编辑增量

工作台新增 `/settings`，编辑所在地、时区、每周工时、雇佣类型、远程要求及排除公司。保存保留来源事实、备份旧画像、增加版本，并使历史审核需重审。已验证 HTTP 保存、即时重筛、旧表单冲突、无效值拒绝、备份内容与 HTML 转义，共 34 项测试通过。时区、工时和雇佣类型暂不用于自动资格判断；工作授权及薪资仍待接入。真实未知条件未代填。


## 薪资与雇佣类型匹配增量

统一资格评估读取 Himalayas 原始结构化字段，识别全职/兼职/实习/合同/临时/志愿者；Other 和未知值待核实。设置页新增薪资底线、币种与周期。只比较同币种同周期，不猜测实际报价。工作台显示来源薪资与类型，岗位版本包含这些字段；旧审核需重审。39 项测试通过，包括边界、缺失、异常区间和版本变化。仍未实现时区重叠计算、工作授权确认、Greenhouse 薪资解析或外部投递。
