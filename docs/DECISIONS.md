# 决策与开放问题

2026-10-16；所有设计选择均可依据用户画像和实测修订。

| ID | 建议决策 | 理由 | 何时重新评估 |
| --- | --- | --- | --- |
| D01 | 单用户、本地优先 | 当前需求是思考方案，尚无多人产品需求 | 明确面向外部用户收费或协作 |
| D02 | 推荐路线 C，同时借 A 建基线 | 自建资格/事实/追踪，复用成熟浏览器能力 | 商用品已满足实际需求且维护收益不足 |
| D03 | 公开岗位接口优先，提交走官方页面 | 企业端提交 API 需要凭据 | 取得明确可用的企业集成授权 |
| D04 | 先两个来源与一个 ATS | 控制维护范围，尽早获得真实数据 | 目标岗位覆盖不足或该 ATS 占比很低 |
| D05 | 硬规则 + 模型抽取/表达 | 资格和提交一致性需要可复算约束 | 离线评估显示需要更复杂模型 |
| D06 | 三态资格判断 | 防止把未知当允许 | 不取消 unknown，只改善补证流程 |
| D07 | 默认只生成本地草稿 | 当前对话授权调研和文件建设，未授权实际申请 | 用户明确选择填写或提交模式 |
| D08 | 提交未知先对账 | 外部副作用无法靠本地事务回滚 | 站点提供可核验的幂等提交机制 |
| D09 | 先固定材料模板，不先做简历编辑器 | 降低范围，让事实正确性先过关 | 用户确有丰富模板/编辑需求 |
| D10 | 不直接 fork 历史 AIHawk 教程 | 原地址已重定向，社区版本未验证 | 完成目标版本的代码、许可和兼容性审查 |

## 待用户补齐

| 问题 | 影响 | 当前处理 |
| --- | --- | --- |
| 岗位类别、资历和行业 | 搜索、必需技能、简历模板 | 不推断为程序员；示例搜索为空 |
| 居住地、工作授权、可接受雇佣方式 | 决定真正可申请范围 | null，资格判断待补证 |
| 英语水平、可用时段、时区重叠 | 面试与团队协作可行性 | null，不编造熟练度 |
| 薪资底线、货币、周期 | 硬筛选或排序 | null，不默认为接受任意薪资 |
| 个人自用还是产品 | 部署、数据许可和用户隔离 | 暂按自用 |
| 可投入开发时间和月费 | 选择 A/B/C/D | 所有费用只是规划区间 |
| 希望自动化到何种程度 | 草稿、上传填表、提交边界 | 仅草稿，无实际外发 |

## 变更记录规则

新证据需要标注日期、来源和影响的决策。对同一用户已经明确授权的范围不重复请求确认；只有扩大范围、事实冲突或材料/授权条件变更时再处理。本文不授予任何实际招聘平台操作权限。
